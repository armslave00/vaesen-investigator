## 视觉布局观察

已渲染并查看完整页面。2505 版是三列框架：左列人物身份和背景；中右上方合并为属性、状态、技能；中右中间分别是天赋、洞察与缺陷、纪念物、优势；底部三列分别是个人装备、临时装备、武器与护甲。资源条放在左列下部，明确分开资源值、生活标准、交易奖励及当前资产。经验圈位于右上方。

旧版和中文附录使用约三分之二宽的左正文区与三分之一宽的右数值区。右列依次是属性、资源、八项状态、十二项技能及经验；左侧放背景、关系、天赋、洞察与缺陷、优势、装备、护甲、武器及纪念物。

现行版的横向四属性/四组技能与 Web 四组属性结构更接近，且有当前资产栏，建议以 2505 分区为主、中文附录字段名称为辅。A4 横版可重新分配间距；若等比例保留现行整页比例，高度撑满 595.276 pt 时内容宽约 768.887 pt，左右会留出约 36.502 pt，不能直接拉伸成 A4。

## 本项目字段映射建议

以下映射来自当前 Web 数据结构，属于导出实现建议。数值应读取 `RulesEngine` 当前结果，不重新执行旧 Excel 公式。技能栏填技能等级，不填本次情境骰池。

| PDF 区域 | 当前角色数据 | 导出处理 |
| --- | --- | --- |
| 姓名、年龄、范型 | `A2`、`D16`、`F16`、`D15` | 年龄和年龄阶段一起显示；玩家 `A4` 可作身份区补充。 |
| 动机、创伤、黑暗秘密 | `I2`、`I5`、`I8` | 保留原换行；与状态区的创伤标记区分。 |
| 四组属性与技能 | 属性 `D20/I20/N20/S20`；技能对应列的 21–23 行 | 每列一属性及其三技能；顺序与 Web 一致。 |
| 肉体、精神状态 | `Y10:Y13`、`AD10:AD13` | `●`、`○`、留空分别保留已选、未选、未填写；崩溃另列。标签采用规则书中文。 |
| 人际关系 | `K11/I12`、`K13/I14`、`K15/I16`、`K17/I18` | 每项保留名字与关系说明。 |
| 天赋 | `A25:A28` 及 `E25:E28`，再加 `progress.extraTalents` | 主卡可列名字；说明放续页。必须保留手动说明覆盖及重复购买的“富有”。 |
| 洞察与缺陷、优势、纪念物 | `U15:U17`、`U6:U8`、`U2:U4` | 三组原值分别输出，不误合并或推断使用次数。 |
| 资源条 | `derived().resource/lifestyle/exchangeBonus/currentAssets` | 显示当前永久资源和实际可用资产，不能用标准资产代替当前余额；可将 `standardAssets` 列作附注。超出规则表域显示未收录。 |
| 装备 | 30–35 行的 `A/E/M` 列 | 保留六栏的名称、说明、加成。现数据没有个人/临时分类，不擅自按名称划分；两区可改为“装备”和“装备说明”。 |
| 武器、护甲 | 武器 32–35 行 `O/V/X/Z/AB`；护甲 `O30/AA30/AC30` | 保留全部四武器及技能字段；伤害、防护、敏捷修正各自独立。 |
| 经验 | `progress.xp`，本场 `W18:AD18` 及 `progress.session` | 可用 XP 用数字表示；八题回答另列“本场经验”，标明待结算/已结算。**不能把八题回答当作经验余额圈**。 |

## 续页与完整性

主卡复用官方信息层级，长文采用明确标注的续页。`A5` 外貌、`AE2` 人物背景、`AE19` 笔记，以及天赋/装备完整说明、经验和资产账本，在官方单页里没有足够位置，应完整续排，避免省略、截断或无限缩小字体。建卡快照和成长阶段可以放“档案记录”续页；成长档注明常规建卡已验证，建卡中的角色注明尚未完成。

PDF 的静态展示不能代替 v2 JSON 存档；导出应取同一时刻的输入与 progress 快照。姓名或装备数字为 0 时应正常显示；null、空字符串与非法数值按现有档案的语义保留，不能用 `value || fallback` 抹掉 0。建议页脚写角色姓名、页码及导出时间，主卡出现续页时给出页码指引。
