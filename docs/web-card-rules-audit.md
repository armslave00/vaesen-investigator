# Web 自动卡的规则核验

核验日期：2026-10-04。复刻依据为 [vaesen 自动卡 v2.0](<../raw-docs/vaesen自动卡by拂晓鵺啼 v2.0.xlsx>)，规则书用于解释与交叉核验。下文中的单元格均指该工作簿；规则页码分别标注原书印刷页与 PDF 文件页序。本次只读取原文件，没有修改 Excel 或规则文档。

## 原卡的自动计算边界

原卡实现的是建卡辅助与文字查表，不是完整的规则执行器。浏览器版应以原卡的输入、公式和查表结果为准。

| 项目 | Excel 来源 | 原卡行为 | 规则核验 |
| --- | --- | --- | --- |
| 年龄分类 | 角色卡 `D16 → F16` | `>=51` 为老年，`>=26` 为中年，`>=17` 为青年，否则“年龄错误” | [年龄表](rulebook/02-player-characters.md#pdf-page-22)，原书 18 页 / PDF 22 页 |
| 年龄点数 | 辅助表 `A16:C18` | 青年属性 15、技能 10；中年 14、12；老年 13、14 | 与年龄表一致 |
| 剩余属性点 | 辅助表 `D16:D18 → 角色卡 P19` | 年龄预算减 `D20、I20、N20、S20` 四个属性之和 | [属性](rulebook/02-player-characters.md#section-09)，原书 20 页 / PDF 24 页 |
| 剩余技能点 | 辅助表 `E16:E18 → 角色卡 T19` | 年龄预算减 `C18` 资源加点与 12 项技能之和 | [技能及资源](rulebook/02-player-characters.md#pdf-page-25)，原书 21 页 / PDF 25 页 |
| 初始资源 | 辅助表 `A2:B12 → 角色卡 A18` | 查所选范型的资源下限 | 10 个基础范型下限均与规则书一致 |
| 总资源 | 角色卡 `A18+C18 → E18` | 资源下限加手填加点；错误时为空字符串 | 技能点兑换资源的原则一致；不自动计算天赋效果 |
| 生活标准 | 资产表 `A2:B9 → 角色卡 C17` | 按资源 1–8 精确查表，未命中时为空字符串 | [资源表](rulebook/02-player-characters.md#pdf-page-26)，原书 22 页 / PDF 26 页；部分译名不同，数值对应一致 |
| 天赋说明 | 天赋表 `B2:C58 → 角色卡 E25:E28` | 根据四个天赋槽所填名称精确查说明，未命中时为空字符串 | [天赋](rulebook/04-talents.md#pdf-page-53)，原书 49 页 / PDF 53 页起 |
| 职业装备提示 | 辅助表 `A2:I12 → 角色卡 A36` | 显示 `职业装备:` 加职业装备原文，查表失败时返回一个空格 | [角色范型](rulebook/02-player-characters.md#section-20)，原书 26–35 页 / PDF 30–39 页 |

技能扣点范围为 `D21:E23、I21:J23、N21:O23、S21:T23`；各项输入所在合并单元格由左上角存值。资源加点 `C18` 只扣一次技能预算。剩余点数是原始减法，没有归零或建卡完成后的冻结逻辑，负数必须保留。

不应因规则书而暗中增加以下自动行为：

- “富有”天赋的描述是资源 +1，但原卡资源公式不读取天赋。选中它只显示说明，不自动增加资源。
- 状态与 XP 是相互独立的 `● / ○` 记录格。原卡不会依选中数量扣骰、累计状态、自动崩溃、增加 XP、消费 XP、购买技能或天赋。
- “资产”、装备加成、护甲防护与敏捷、武器伤害与范围等均为手填内容，没有装备数据库查表或联动公式。
- 天赋含有适用场景、次数、忽略状态、奖励骰等文字条件。原卡不会解析文字并自动执行。
- 升级后技能提高仍影响原有剩余技能点公式，原卡没有“成长模式”另算预算。

## 建卡规则与原卡输入的区别

基础建卡规则为四个属性至少 2，非主要属性最多 4，主要属性最多 5；技能通常最多 2，范型主要技能最多 3；初始选一个范型天赋；初始资源从范型下限起，每提高 1 点消耗 1 点技能预算，不超过该范型范围。来源分别是[属性](rulebook/02-player-characters.md#section-09)、[技能](rulebook/02-player-characters.md#section-10)、[天赋](rulebook/02-player-characters.md#section-11)和[资源](rulebook/02-player-characters.md#section-14)，原书 20–21 页 / PDF 24–25 页。[玩家建卡手册](player-guide/README.md) PDF 2、4–5 页也收录这些规则。

Excel 没有对年龄、属性、技能或资源加点设数值阻断验证。因此规则检查适合以提示呈现，不应强制裁剪数值或改写输入。工作表 XML 中的数据验证仅覆盖：

- 范型下拉：辅助表 `A2:A12`，含 11 个范型。
- 首个天赋槽：`INDIRECT($D$15)`，取所选范型的三个初始天赋。
- 纪念物：36 项 D66 纪念物列表。
- 状态与 XP：`● / ○` 选项，且允许空白。

原卡中未选择范型时，初始资源、总资源与生活标准返回空字符串。已选择合法范型但资源加点为空时，总资源等于范型下限。非法年龄使年龄显示“年龄错误”，其剩余点数 `VLOOKUP` 没有 `IFERROR`，因未命中而产生 `#N/A`。Web 可以给出清楚的错误呈现，但不能把未命中解释成合法的 0 点预算。

## 一致性验收要点

- 对 16、17、25、26、50、51 岁以及空年龄检查年龄分界；对每组年龄验证完整预算与负数剩余。
- 对 11 个范型逐个核验下限、提示文字、三个初始天赋。重点覆盖牧师上限 5 和扩展吸血鬼猎人。
- 资源加点每增加 1，总资源加 1、剩余技能点减 1；设置 0、留空、超范围以及无范型时也应按原式呈现。
- 对资源 1–8 与范围外值检查生活标准查表；对每个天赋名称检查说明，包括空槽与未命中名称。
- 选择“富有”、切换状态、切换 XP 圆点、填写护甲与武器时，不应改变任何原卡没有关联的计算。
- 保存、导入、导出与刷新后应保留独立记录格、输入文本和数值；不能仅比较原表的空白缓存结果来证明已重新计算。
