# Web 角色卡的规则计算规范

核验日期：2026-10-04。本规范用于在 Excel 复刻基线 `ff4de6f` 上按本仓库规则书补充自动计算；其新增行为替代[复刻阶段核验记录](web-card-rules-audit.md)中“保持原表无联动”的实施建议。原始 Excel 与 PDF 不修改。页码同时标注原书印刷页与 PDF 文件页序。

## 建卡点数与上下限

年龄预算为青年 17–25 岁：属性 15、技能 10；中年 26–50 岁：14、12；老年 51 岁及以上：13、14。[年龄表](rulebook/02-player-characters.md#pdf-page-22)，原书 18 页 / PDF 22 页。

四个属性分别为体能、精准、逻辑、共情。建卡时每项为整数，最低 2，主要属性最高 5，其余最高 4。初始技能每项为整数，最低 0，主要技能最高 3，其余最高 2。[属性](rulebook/02-player-characters.md#section-09)，原书 20 页 / PDF 24 页；[技能](rulebook/02-player-characters.md#section-10)，原书 21 页 / PDF 25 页。

上述是第二章常规点数分配法。第十一章另有可选人生轨迹法，其年龄扣属性步骤仅要求初始属性不能为 0，可能产生属性 1；若暂不实现该路线，应将检查标成“常规建卡检查”，对旧卡给提示并保留输入。[背景故事表](rulebook/11-background-tables.md#pdf-page-218)，原书 214 页 / PDF 218 页。

设 `A(age)` 为属性预算，`S(age)` 为技能预算，`a_i`、`s_i` 为**初始分配**，`r0`、`rMax` 为范型资源下限及上限，`rInvest` 为消费技能点购买的资源点：

```text
remainingAttributes = A(age) - Σ a_i
remainingSkills = S(age) - Σ s_i - rInvest
creationResources = r0 + rInvest
0 <= rInvest <= rMax - r0
```

每提升 1 点初始资源消耗 1 点技能预算，建卡时资源不能超过范型范围。游戏开始后正常提高资源通过购买天赋；生活水平改变的剧情事件也可能改变资源。[资源](rulebook/02-player-characters.md#section-14)，原书 21 页 / PDF 25 页。角色定稿应检查每项边界与预算，避免通过输入裁剪隐藏分配错误。

范型采用规则书的主属性、主技能和资源范围；已确认 Excel 需要修正的数值是牧师上限 `5 → 6`，[牧师](rulebook/02-player-characters.md#section-26)，原书 31 页 / PDF 35 页。“蛮力”对应标准技能“力量”，[仆人](rulebook/02-player-characters.md#section-28)，原书 33 页 / PDF 37 页。吸血鬼猎人源自 Excel 注明的《喀尔巴阡》扩展，本仓库未附扩展规则，保留现有数据并注明核验范围。

## 成长、天赋与永久资源

每消耗 5 XP，可以使一项技能提高 1 级，或购买一个新天赋。技能最高 5；新天赋可来自任何范型或通用天赋，不受最初范型限制。[经验](rulebook/02-player-characters.md#section-19)，原书 25 页 / PDF 29 页；[天赋](rulebook/04-talents.md#pdf-page-53)，原书 49 页 / PDF 53 页。

- 初始天赋必须且只能选一个，来自自己的范型提供的三个选项。
- “富有”每次使资源 +1，明确可以重复购买。[富有](rulebook/04-talents.md#section-65)，原书 55 页 / PDF 59 页。
- 其他天赋购买的是“新天赋”。实现应避免重复购入已拥有的天赋；“富有”作为规则明确的例外。
- XP 成长规则没有提高属性的选项，因此不提供“花 XP 提高属性”。重创洞察/残缺的奖励是技能检定调整，也不等同于永久属性提升。[重创表](rulebook/05-conflict-and-injuries.md#pdf-page-69)，原书 65–66 页 / PDF 69–70 页。

设 `growth_i` 为技能成长次数，`wealthyCount` 为已购“富有”的次数，`storyResourceAdjustment` 为明确记录的 GM 剧情调整：

```text
skill_i = s_i + growth_i                （范围 0–5）
resources = creationResources + wealthyCount + storyResourceAdjustment
growthCost = 5 × (Σ growth_i + 所有后天购入天赋的次数)
```

“富有”购买次数本身是上述后天天赋次数的一部分，不应再重复收取 XP。职业资源上限用于建卡，不能用于阻止后天购买“富有”突破初始上限；这是结合资源章节“游戏开始后”和可重复购买天赋所作的解释。

本书两张资源表只定义资源 `1–8`，没有写出独立的“永久资源不得超过 8”句子。[资源表](rulebook/02-player-characters.md#pdf-page-26)，原书 22 页 / PDF 26 页；[资源调整值](rulebook/05-conflict-and-injuries.md#pdf-page-77)，原书 73 页 / PDF 77 页。**不把表域推定成成长硬上限**：资源 8 仍可支付 5 XP 购买“富有”到 9，保留合法正整数资源；对于 9 及以上不编造生活标准、交易奖励和标准资产，返回未收录提示并由 GM 决定补充映射。不得静默截断资源或把未知表值映射为 0。

初始分配与成长增量应分别持久化。完成建卡后显示的是成长后的技能，但建卡剩余预算仍只由 `a_i、s_i、rInvest` 计算。否则后天成长会错误地再次扣建卡技能点。调整角色年龄也不应自动移除已购买的技能或天赋；需要明确进入修改建卡分配的操作。

## XP 结算

[经验问题](rulebook/02-player-characters.md#pdf-page-29)，原书 25 页 / PDF 29 页的八个问题：参与本次游戏、与自在之物对峙、辨别新种类、黑暗秘密影响自己、为保护他人犯险、学会新事物、开发大本营、做出非凡行动。每个“是”获得 1 XP；参与者总是至少获得第一点。

```text
sessionXp = 1 + 第 2–8 个问题的 yes 值 （参与场次 1–8，第一题保底）
xpBalance = carriedXp + Σ 已结算场次 sessionXp
            + gmXpAdjustment - growthCost - mementoRepairCost
mementoRepairCost = 修复/重获旧纪念物的次数 × 1 XP
```

修复或重获旧纪念物消耗 1 XP；选择全新纪念物前须经历一次完整谜题没有纪念物。[装备与纪念物](rulebook/02-player-characters.md#section-15)，原书 22 页 / PDF 26 页。它是 5 XP 成长以外的独立花费，不能把所有消费都假定为 5 的倍数。

需要一次明确的“结算本场”操作，把勾选结果增加到 XP 余额并记入场次记录，避免勾选、刷新或重复点击多次发放。第一题留空或为“否”也保留参与者的基础 1 XP，因此其余两题为“是”应获得 3 XP。“开始下一场”须在本场结算后执行，避免丢失未结算回答。技能/天赋购买须在一次事务内完成 XP 扣除与能力增加，余额不足、技能已为 5、非重复天赋已拥有时都不产生花费。撤销购买应同时撤销能力与返还 XP，不能只改变显示列表。

## 生活标准、交易奖励与资产

永久资源自动查下面的表，不把资产余额当资源。标准资产与交易奖励来源为[资源调整值](rulebook/05-conflict-and-injuries.md#pdf-page-77)，原书 73 页 / PDF 77 页；生活标准译名采用[第二章资源表](rulebook/02-player-characters.md#pdf-page-26)，原书 22 页 / PDF 26 页。

| 资源 | 生活标准 | 交易奖励骰 | 标准资产 |
| --- | --- | --- | --- |
| 1 | 赤贫 | -1 | 0 |
| 2 | 贫穷 | 0 | 0 |
| 3 | 挣扎 | 0 | 1 |
| 4 | 经济稳定 | +1 | 2 |
| 5 | 中产 | +1 | 3 |
| 6 | 小康 | +2 | 5 |
| 7 | 富有 | +3 | 8 |
| 8 | 大富豪 | +5 | 12 |

资源检定掷资源值个骰子；每个成功可用于购买可得性 1 的物品，可得性 3 需要 3 个成功，可以汇集同伴成功。资产也能支付购买；购物只减少可用资产，不能减少永久资源。[准备装备](rulebook/05-conflict-and-injuries.md#section-31)，原书 73 页 / PDF 77 页。与不愿让出物品的 NPC 对抗时使用操控人心加交易奖励，不能用资产代替对抗成功。[在谜题中购物](rulebook/05-conflict-and-injuries.md#section-32)，同页。

标准资产是查表值，当前可用资产是独立余额，应分别呈现。玩家可输入已有骰子的成功数与购买消耗，Web 只记账，不自动掷骰：

```text
availableAssets = openingAssets + enteredResourceSuccesses
                  + explicitAssetAdjustment - assetSpending
```

余额不得小于 0；失败的超额消费不记账。将 `openingAssets` 初始化为本次开始时的标准资产，可用于新建角色；从旧卡迁入则应尊重已记录余额，不覆盖成查表值。

**恢复时间的译文存在边界不清：**购物章节说资产消耗持续到下一谜题，并由资源检定成功骰增加到资产上，没有明确列出“下一谜题先无条件恢复整张标准资产表，再加成功”的流程。保守实现为显式“增加资源检定成功数”与“开始新谜题”记录操作；若后者重置余额为标准资产，须在按钮旁清楚注明这是当前应用选择的处理方式。资源提升时更新标准资产提示，不应在每次重算时把已花资金自动补满。

## 必要交互与检验

- 建卡与游戏中成长分开：定稿检查初始预算，成长以余额与购买记录驱动。
- 自动显示“富有”次数、总资源、生活标准、交易奖励及标准资产；当前资产由消费与补充记录维护。
- 结算场次默认第一题为“是”；显示本场 XP 并明确结算，结算记录防重复。
- 技能 5 时升级、XP 不足、资产不足、重复结算、未结算就开始下一场均应没有部分执行。
- 资源 8 时购“富有”应正常到 9 并扣 5 XP，提示表中未收录其生活标准、交易奖励与标准资产，保留当前资产余额。
- 验证一次从资源 5 到 6 的“富有”成长：资源 +1、标准资产 3 → 5、交易奖励 +1 → +2、XP -5；当前已消费资产不会因重算无条件重置。
- 按规则修正默认数据、增加计算与记账即可；不自动掷骰，不自动判断 GM 认定的剧情与条件。
