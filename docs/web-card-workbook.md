# 自动卡工作簿清单

本清单依据 `raw-docs/vaesen自动卡by拂晓鵺啼 v2.0.xlsx`，用于 Web 角色卡的逐格核验。工作簿只读提取，原文件没有重算、保存或修改。完整值、公式、保存时的计算结果、格式、校验、命名区域和合并关系保存在 `web/data/workbook.json`；`scripts/extract-workbook.py` 可重复生成同一清单。

## 自动计算

### 年龄与点数

角色卡 F16 根据 D16 依次判断 `>=51`、`>=26`、`>=17`，返回「老年(51+)」「中年(26-50)」「青年(17-25)」，否则返回「年龄错误」。原表没有四舍五入年龄。

| 年龄组 | 属性总点数 | 技能总点数 |
| --- | ---: | ---: |
| 青年(17-25) | 15 | 10 |
| 中年(26-50) | 14 | 12 |
| 老年(51+) | 13 | 14 |

辅助表 D16:D18 计算对应年龄的属性剩余：总点数减 `SUM(角色卡!D20,角色卡!I20,角色卡!N20,角色卡!S20)`。角色卡 P19 依据 F16 精确查回该剩余值。

辅助表 E16:E18 计算技能剩余：总点数减 `SUM(角色卡!C18,角色卡!D21:E23,角色卡!I21:J23,角色卡!N21:O23,角色卡!S21:T23)`。范围内的合并占位单元格为空。角色卡 T19 依据 F16 精确查回该剩余值。资源投入 C18 与 12 项技能共享预算；资源基础下限 A18 不扣预算。

`SUM` 对空白和被作为文本存储的输入忽略，对普通数值累加。预算可为负值，原表不会强制禁止继续输入。年龄无效时，P19 和 T19 是 `#N/A`，没有 `IFERROR` 包裹。

### 天赋

E25:E28 各使用 `IFERROR(VLOOKUP(A行,天赋表!B2:C58,2,FALSE),"")`。它们在 57 个完整名称中做精确匹配，返回源表 C 列原文说明，未匹配返回空字符串。说明里的加成、减伤等文字不会进一步修改属性、技能、护甲或武器。

辅助表中的 85 个其它公式是单格引用，用来复用天赋名称、泛型名称和泛型下拉选项；与上面的 6 个预算公式合计 91 个公式。所有展开后的公式和保存缓存均保留在 JSON 中，未把它们替换成静态结果。

## 数据校验与条件格式

角色卡共有 4 条数据校验：

1. 状态与经验共 16 个单格使用字面列表 `"●,○"`。
2. A25:D25 使用 `INDIRECT($D$15)`，引用当前泛型的命名区域。
3. U2:AD4 使用命名区域「纪念物」。
4. D15:H15 使用辅助表 A2:A12；这条校验存储在 Excel 扩展命名空间。

13 个命名区域为 11 个泛型天赋区域、纪念物表 B2:B37、通用天赋表 B35:B58。所有校验均允许空白。其余字段没有工作簿级数据校验。

角色卡有 21 条条件格式规则，其中 20 条根据泛型把主要属性或主要技能的标签（部分还包括数值单元格）变为 `#50808e`，1 条在总资源 E18 超过该泛型上限时变红。其它工作表的 6 条规则仅使用 `MOD(ROW(...),2)=0` 做交替行底色，没有计算上的约束。

主要属性和技能提示应该根据实际条件格式的区域和表达式核验，而不是直接把辅助表中的两个名称当成显示逻辑：源表「仆人」的主要技能写为「蛮力」，显示标签写为「力量」，但原条件格式明确高亮 A23:C23。

## 原表边界与保留事项

- 打开空白原表时，F16 的保存值为「年龄错误」，P19、T19 为 `#N/A`。A18、E18、C17、E25:E28 的缓存都是空字符串；A36 的缓存是一个空格。清单明确区分公式返回空字符串、真正空单元格和错误值。
- 资源超上限条件格式查找范围是辅助表 A2:C11，遗漏吸血鬼猎人的第 12 行。因此该泛型超出资源上限时，原表的资源不会变红。Web 若以忠实复刻为目标，不能静默扩展查找范围。
- 部分文字保留原表的术语、标点和不换行空格。普通显示可合理排版，数据和查表匹配应保留完整原值。
- 状态标记、经验标记、优势、洞察与缺陷、装备、护甲和武器完全手动填写。原表没有骰池公式、状态减值联动、经验累计总数、升级消耗自动计算或装备加成自动汇总；增加此类能力需要与原本的自动卡行为明确区分。
- 原表没有 VBA、脚本、外链工作簿、图表、形状控件或嵌入图片。原生辅助表格提供泛型清单的筛选与条纹格式，没有额外的结构化公式。
- 本次提取保留保存缓存作为基线，但它本身不证明其它输入情景在 Excel 中的运行结果。输入变化、边界和错误传播应由独立公式核验检查，不以缓存或公式总数替代运行验证。

JSON 中每个公式记录 `dependencies`，每个可编辑字段记录 `affectedFormulas`；前者保留直接 A1 引用，后者追踪通过辅助表到角色卡结果的传递关系。源文件 SHA-256 用来验证提取对应版本。
