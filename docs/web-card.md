# Web 自动角色卡

当前版本以仓库内中文规则书为准，源自 `raw-docs/vaesen自动卡by拂晓鵺啼 v2.0.xlsx`，采用北欧调查员档案册风格。忠实复刻基线已提交为 `ff4de6f`，分支 `codex/vaesen-web-card`；原 Excel、PDF 和提取的 `workbook.json` 未修改。

[打开网页版](https://vaesen-investigator-archive.auseaia01.chatgpt.site)（仅当前所有者可访问）。规则修正版已于 2026-10-05（北京时间）发布为版本 2，托管源码提交为 `9ad83dd34b6f4b36782f7c3a42839a52372d6e02`。

## 使用

运行 `npm run dev`，打开显示的 HTTP 地址。先填泛型、年龄、属性、技能、资源加点及一项职业天赋。常规建卡校验通过后，点击“完成建卡”；初始分配冻结为快照，后续成长不再扣初始预算。数值异常以提示呈现，不静默裁剪输入。

已有角色或使用可选人生轨迹建卡的角色可以“将旧角色转为成长档”。这会保存当前分配并明确标记为导入；不假定它通过常规建卡。成长后原始年龄、泛型、属性、技能和天赋名称默认锁定，可通过“修订原始数值”进行 GM 认可的调整。

检定助手预览技能或恐惧骰池。它会应用对应普通状态、常驻天赋、已选择的情境奖励、实际使用的装备、武器、护甲敏捷惩罚、帮助及优势，并区分崩溃行动资格、伤害和防护骰。情境条件、次数和 GM 裁定需玩家确认；不自动掷骰或消费优势。替代技能请直接选择替代后的技能。

装备栏可手填，或通过规则表预设替换指定栏位。资源表列出标准资产和交易奖励；当前资产单独记账，支出不会扣永久资源，恢复标准资产需明确操作。手填资产覆盖已有余额时保留绝对值，随后记账操作会接管为独立余额。

八个经验圆点记录本场回答，参与至少计 1 XP。点击“结算本场经验”只入账一次；“开始下一场”清除回答并开放下一次结算。每 5 XP 可提升一项技能一级（最多 5）或购买一个天赋；富有可以重复购买，每份资源 +1。修复或重获旧纪念物可消费 1 XP。所有经验与资产调整记录原因和余额。

## 保存与迁移

输入自动保存于当前浏览器，JSON 导出后可在相同 Excel 来源版本的网页中导入。不同网址分别保存，更换设备或网址前请导出。导入会替换当前档案，清空有确认框。

当前档案格式为 `vaesen-web-card`、版本 2，包含：

- 原卡 110 个可编辑字段，包括圆点、零值、空值、换行和天赋说明手动覆盖。
- 建卡快照、角色阶段、成长天赋、可用 XP、当前资产。
- 场次编号、是否已结算和经验/资产账本。

旧版本 1 档案可以无损迁移原字段；不从圆点推断累计 XP 或已结算状态。已有总经验可通过“经验调整”记入，确认角色已成长后显式转为成长档。导入依据字段与账本 schema 验证，合法档案不再受旧 5 MB 文件限制；文本每栏最多 200,000 字符，账本最多 5,000 条。

## 数据与计算

- `scripts/extract-workbook.py` 只读提取原工作簿，保留 6 张表、440 个非空常量、102 个公式、110 个输入区域与命名/校验/条件格式资料。`web/engine.js` 继续执行原 Excel 公式，用于历史基线回归。
- `scripts/extract-rules.py` 从本地规则章节生成 `web/data/rules.json`：10 个基础范型和 1 个未核验扩展，54 个基础天赋和 3 个扩展天赋，8 档资源、3 种护甲、23 种武器、42 项装备、掩体与服务。各项保留书页与 Markdown 来源。
- `web/rules-engine.js` 是当前应用的纯规则层，封装建卡、成长、XP/资产事务和骰池计算。非法消费、重复结算和余额溢出原子拒绝。
- `web/rule-storage.js` 验证版本 2 档案并迁移版本 1；旧 `web/storage.js` 保留基线接口。
- `web/app.js` 与 `web/rules-ui.js` 只渲染与调用规则层；保存及可选 WebMCP 共用同一计算流程。

[完整字段与原公式清单](web-card-workbook.md)、[差异与处理依据](web-card-rules-audit.md)、[建卡与账本规范](web-rules-calculation-spec.md)、[骰池规范](web-dice-rules-spec.md)可用于核对实现。

## 验证

原 72 项工作簿/存档测试保留，期望由独立 OOXML 提取生成。当前共 125 项测试通过。新增测试按规则原文给出独立预期，涵盖完整规则资料来源、成长与账本事务、版本迁移、状态与天赋、恐惧、武器、护甲及资源 8→9 的表域边界。

浏览器流程核验了常规建卡、冻结分配、一次性经验结算、技能/富有购买、资产支出与刷新恢复，技能和恐惧骰池、崩溃、护甲、徒手与情境天赋、旧档案采纳、手写说明和零资产，以及超过旧 5 MB 限制的合法档案导入与刷新恢复。110 个原输入栏全部存在；桌面、390px 和 320px 视口没有整体横向溢出，宽表按需横向滚动。

支持 `document.modelContext` 的浏览器会注册 `read_investigator_card`、`update_investigator_fields` 两个可选原生 WebMCP 工具。核验浏览器未提供该接口，原生注册/调用尚未实测；普通网页功能不依赖它。

## 边界

吸血鬼猎人扩展不在现有基础书中，保留原卡并明示未核验。应急医学按中文正文免除医学对应的物理状态，公开英文原文/译注矛盾；双手武器专精按正文的双武器条件。资源表只列 1–8，更高资源保留，不推造生活标准、交易奖励与标准资产，也不把 8 推定为规则硬上限。

## 构建与托管

无前端框架和运行时依赖，使用 `npm test` 与 `npm run build`。构建复制静态源码与数据到 `web/dist/`。`web/.openai/hosting.json` 保存既有 Sites 身份，静态目录为 `dist`，继续使用相同私有网址。发布准备使用忽略的独立源码检出目录，托管源码提交不改变本仓库的基线提交。
