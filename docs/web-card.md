# Web 自动角色卡

当前版本以仓库内中文规则书为准，源自 `raw-docs/vaesen自动卡by拂晓鵺啼 v2.0.xlsx`，采用北欧调查员档案册风格。忠实复刻基线已提交为 `ff4de6f`，分支 `codex/vaesen-web-card`；原 Excel、PDF 和提取的 `workbook.json` 未修改。

[既有 Sites 托管版本](https://vaesen-investigator-archive.auseaia01.chatgpt.site)（仅当前所有者可访问）。规则修正版已于 2026-10-05（北京时间）发布为版本 2，托管源码提交为 `9ad83dd34b6f4b36782f7c3a42839a52372d6e02`；本轮移除旧模式、PDF 导出与 GitHub Pages 配置尚未发布到该地址。

## 使用

先运行 `npm ci` 安装依赖，再运行 `npm run dev`，打开显示的 HTTP 地址。先填泛型、年龄、属性、技能、资源加点及一项职业天赋。常规建卡校验通过后，点击“完成建卡”；初始分配冻结为快照，后续成长不再扣初始预算。数值异常以提示呈现，不静默裁剪输入。

成长后原始年龄、泛型、属性、技能和天赋名称默认锁定，可通过“修订原始数值”进行 GM 认可的调整。修订不重新扣除已保存的初始预算。网页采用第二章常规建卡流程，可选人生轨迹建卡尚未实现。

检定助手预览技能或恐惧骰池。它会应用对应普通状态、常驻天赋、已选择的情境奖励、实际使用的装备、武器、护甲敏捷惩罚、帮助及优势，并区分崩溃行动资格、伤害和防护骰。情境条件、次数和 GM 裁定需玩家确认；不自动掷骰或消费优势。替代技能请直接选择替代后的技能。

装备栏可手填，或通过规则表预设替换指定栏位。资源表列出标准资产和交易奖励；当前资产单独记账，支出不会扣永久资源，恢复标准资产需明确操作。手填资产覆盖已有余额时保留绝对值，随后记账操作会接管为独立余额。

八个经验圆点记录本场回答，参与至少计 1 XP。点击“结算本场经验”只入账一次；“开始下一场”清除回答并开放下一次结算。每 5 XP 可提升一项技能一级（最多 5）或购买一个天赋；富有可以重复购买，每份资源 +1。修复或重获旧纪念物可消费 1 XP。所有经验与资产调整记录原因和余额。

## 保存与导入导出

输入自动保存于当前浏览器，仅接受当前规则版 v2 JSON 档案，且须与相同 Excel 来源版本匹配。不同网址分别保存，更换设备或网址前请导出。导入会替换当前档案，清空有确认框。

当前档案格式为 `vaesen-web-card`、版本 2，包含：

- 原卡 110 个可编辑字段，包括圆点、零值、空值、换行和天赋说明手动覆盖。
- 建卡快照、角色阶段、成长天赋、可用 XP、当前资产。
- 场次编号、是否已结算和经验/资产账本。

成长档必须包含通过常规建卡后保存的有效初始快照；角色阶段不能绕过“完成建卡”切换。导入依据字段、快照与账本 schema 验证，并按规则重新核对快照中的范型、年龄预算、属性与技能范围、资源投资和点数总和，不信任单独的“已验证”标记。这项检查只针对历史初始分配，允许后续 GM 修订当前数值；不支持其他档案版本。已有总经验可通过“经验调整”记入。合法档案不设整份文件的固定 5 MB 上限；文本每栏最多 200,000 字符，账本最多 5,000 条。

## 数据与计算

- `scripts/extract-workbook.py` 只读提取原工作簿，保留 6 张表、440 个非空常量、102 个公式、110 个输入区域与命名/校验/条件格式资料。`web/engine.js` 继续执行原 Excel 公式，用于历史基线回归。
- `scripts/extract-rules.py` 从本地规则章节生成 `web/data/rules.json`：10 个基础范型和 1 个未核验扩展，54 个基础天赋和 3 个扩展天赋，8 档资源、3 种护甲、23 种武器、42 项装备、掩体与服务。各项保留书页与 Markdown 来源。
- `web/rules-engine.js` 是当前应用的纯规则层，封装建卡、成长、XP/资产事务和骰池计算。非法消费、重复结算和余额溢出原子拒绝。
- `web/rule-storage.js` 只验证当前规则版 v2 档案；`web/storage.js` 保留原 Excel 复刻基线接口，供历史回归对照。
- `web/app.js` 与 `web/rules-ui.js` 只渲染与调用规则层；保存及可选 WebMCP 共用同一计算流程。

[完整字段与原公式清单](web-card-workbook.md)、[差异与处理依据](web-card-rules-audit.md)、[建卡与账本规范](web-rules-calculation-spec.md)、[骰池规范](web-dice-rules-spec.md)可用于核对实现。

## 验证

全套 141 项测试通过，原 72 项工作簿/存档测试保留，期望由独立 OOXML 提取生成。新增测试按规则原文给出独立预期，涵盖完整规则资料来源、常规建卡定稿、历史快照重验、成长与账本事务、当前规则档保存与恢复、拒绝不支持的档案版本、状态与天赋、恐惧、武器、护甲及资源 8→9 的表域边界；9 项 PDF 测试检查实际生成的文件内容与分页。

浏览器流程核验了常规建卡、冻结分配、一次性经验结算、技能/富有购买、资产支出与刷新恢复，技能和恐惧骰池、崩溃、护甲、徒手与情境天赋、手写说明和零资产，以及超过 5 MB 的合法档案导入与刷新恢复。110 个原输入栏全部存在；桌面、390px 和 320px 视口没有整体横向溢出，宽表按需横向滚动。

支持 `document.modelContext` 的浏览器会注册 `read_investigator_card`、`update_investigator_fields` 两个可选原生 WebMCP 工具。核验浏览器未提供该接口，原生注册/调用尚未实测；普通网页功能不依赖它。

## 边界

吸血鬼猎人扩展不在现有基础书中，保留原卡并明示未核验。应急医学按中文正文免除医学对应的物理状态，公开英文原文/译注矛盾；双手武器专精按正文的双武器条件。资源表只列 1–8，更高资源保留，不推造生活标准、交易奖励与标准资产，也不把 8 推定为规则硬上限。

## PDF 导出

顶部“导出 PDF”直接下载人物卡，参照 [Free League 官方 2505 横版人物卡](https://freeleaguepublishing.com/wp-content/uploads/2023/08/Vaesen-Character-Sheet-2505.pdf) 的信息分区，采用同样的 279 × 216 mm 页面尺寸。使用中文字段与本项目的墨绿、铜色线条重新绘制；没有复制官方插图。打印时可选横向 Letter 或适合纸张。

首页显示身份、四组属性与十二技能、状态、关系、天赋、纪念物、优势、洞察与缺陷、六项装备、四项武器及护甲。资源、交易奖励、当前可用资产、标准资产、可用 XP 与本场待结算经验分别呈现，均读取当前规则层，导出过程中不重算原 Excel 公式。游戏阶段保留初始点数快照；不会将已花资产恢复为标准资产，也不会将本场八项回答当成 XP 余额。

天赋手写说明、成长天赋、武器技能、背景、笔记、经验回答和账本完整排入续页；首页放不下的文字明确提示续页。保留换行与零值。下载前先获取角色快照，字体加载期间继续编辑不会混入同一份 PDF。PDF 用于阅读和打印；继续编辑或换设备请保留 JSON 档案。

`web/pdf-card.js` 提供纯快照与 PDF 生成函数，`web/pdf-export.js` 负责浏览器下载。中文使用本地 [Noto Sans SC Regular / OFL](../web/fonts/README.md)，字体约 10 MB，只在首次导出时加载；每份 PDF 仅嵌入实际使用的字形，离线阅读不依赖外部字体。未收录的字符以 Unicode 编码标注并在下载提示中说明。

[参考模板核验和字段映射](pdf-character-sheet-reference.md)记录了来源、尺寸及版式选择。PDF 自动测试直接检查字节中的中文映射、字体嵌入、数值和分页后的完整内容；样例经 Poppler 渲染核对。

## 构建与托管

使用 Node.js 24 运行 `npm ci`、`npm test`、`npm run build`，再执行 `node scripts/check-pages-build.mjs`。esbuild 将 PDF 依赖打包，源码、规则数据、字体与 `.nojekyll` 进入 `web/dist/`；网页运行不需要服务器端 Node.js，也不使用 CDN。开发服务器启动时生成 PDF 包，修改 PDF 模块后需重启 `npm run dev`。

[GitHub Pages 工作流](../.github/workflows/github-pages.yml) 在 `master` 推送后自动测试、构建、检查项目子路径资源并部署；PR 仅验证。首次需要在仓库 Settings → Pages 将 Source 设为 GitHub Actions，详见 [部署说明](github-pages.md)。本站链接和字体路径均支持 `/vaesen-investigator/` 子路径。工作流已配置与本地验证，不代表远程 Pages 已启用或部署成功。

`web/.openai/hosting.json` 仍保存既有 Sites 身份，私有托管地址是此前发布的规则修正版，本轮 GitHub Pages 和 PDF 更新尚未发布到该服务。不同网址的本地存档相互独立，迁移网站前先导出 JSON 档案。
